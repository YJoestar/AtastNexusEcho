# NEXUS ECHO — Evidence implementation audit

## The specification that was audited

The brief asked for the existing `EVIDENCE_ECOSYSTEM.md`. **No file with that name exists in the repository.** The only ecosystem document is `EVIDENCE_ECOSYSTEM_AUDIT.md`, written in the previous round from the real library, and the earlier evidence brief it answers. That audit was used as the specification. Design principles come from `EVIDENCE_REFERENCE_NOTES.md`, which is weaker than asked: every network fetch was blocked, so nothing there is SOURCED, only search-snippet summaries or unverified memory (the file says so).

## Authority rule applied

The game is the authority. The canonical case NX-037 has 66 records in **8 media** (photograph, surveillance, document, fragment, map, personnel, note, audio). The brief's wider vocabulary (letter, email, poster, receipt, lab report, tape, forensic report, message, screenshot…) has no records in the story, so none was created. `npm run evidence:lock` holds for all 66 records.

## Type decisions

| Brief type | Decision | Reason |
|---|---|---|
| Photograph, Polaroid | KEEP (PHOTOGRAPH) | 12 records, location + device + time on all |
| CCTV / camera export | KEEP (SURVEILLANCE) | 9 DVR frames, tapes 1–9; real series |
| Handwritten note, diary page | KEEP (NOTE) | 9 records |
| Document, letter, lab/forensic report | KEEP as DOCUMENT only | 9 institutional forms; no letter or lab record exists |
| Fragment, object | KEEP (FRAGMENT) | 10 physical recoveries |
| Map, floor plan | KEEP (MAP) | 5 facilities drawings |
| ID / personnel | KEEP (PERSONNEL) | 6 forms; densest clue type |
| Cassette, voice recording | KEEP (AUDIO) | 6 dictaphone records; **no audio files attached** |
| Email, message, screenshot, terminal output, access log | REJECT | no such record in canon; would need invented content |
| Poster, newspaper, receipt, ticket, envelope | REJECT | same |
| VHS, dashcam, bodycam, phone video | REJECT | no footage exists; video would be faked |
| Fingerprint, DNA, sample result | REJECT | no forensic-lab storyline in canon |

## Problems found and fixed in this round

- Every medium used one inspector with the same chrome → per-medium instruments.
- Board cards cropped every thumbnail to the same box → medium framing.
- Surveillance overlay repeated the device and source (`DVR NODE B-04` twice) → deduplicated.
- Inspection views overflowed horizontally at 390 px (scrubber, audio grid, single-column grid min-content) → fixed; capture now reports 32/32 clean.
- Sticky "ADD TO BOARD" bar floated 92 px above the bottom inside the admin overlay (offset meant for the player nav) → anchored at the bottom there.
- Workstation system bar overlapped its text on a phone → title/labels collapse below `md`.
- Archive did not pass its catalog to the inspector, so frame stepping would have shown nothing in production → wired.
- Handwritten notes rendered in a fallback sans (Segoe Print etc. absent on Linux) → see the realism section of EVIDENCE_SHOWCASE.md.

## Still weak (honest)

- Audio has no audio. Fragments have no TEMPORAL clue. Six of nine surveillance frames are BACKGROUND importance. Notes are the least connected medium. These are story/data facts; they were not "fixed" because that would change canon.
- Fragment files are RGBA PNGs with a `.jpg` extension (1.2 MB of the full set).
- Pinch/pan/tap were exercised only in emulated mobile Chromium and jsdom, not on a physical device.
- The older ENHANCE controls and zoom buttons are below 44 px.
- Map "linked records" falls back to same-location records, which for the 5 maps includes everything filed under FACILITIES ENGINEERING.
